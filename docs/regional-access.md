# صلاحيات المستخدم حسب المناطق — مكّن

## الاستخدام

من **المستخدمون والصلاحيات ← إدارة الحساب ← نطاق المناطق**:

1. أبقِ الدور الحالي مثل Editor أو Watcher وحدد الصفحات والعمليات كالمعتاد.
2. اختر «مناطق محددة فقط»، ثم منطقة الرياض أو عدة مناطق من القائمة القابلة للبحث.
3. احفظ الحساب وأكد في النافذة المخصصة. يسري التعديل على الطلب التالي دون تسجيل خروج.
4. «جميع المناطق» يزيل القيد الجغرافي فقط؛ لا يمنح صلاحية صفحة أو عملية.

## القرارات المعتمدة

- النطاق يخص المستخدم، ويتقاطع مع جميع أدواره ومنحه ومنعه الصريح ونطاق صفحاته. لا تنشأ أدوار منفصلة لكل منطقة.
- منطقة مشتركة واحدة تكفي **للعرض**. التعديل والحذف والتفعيل والتحويل والمتابعة تتطلب أن تكون **جميع مناطق السجل** ضمن نطاق المستخدم.
- بطاقة مرتبطة بالرياض وجدة تظهر لمستخدم الرياض للقراءة. لا يستطيع تغييرها أو حذف جدة لإزالة القيد. صاحب صلاحية الرياض وجدة يستطيع تعديلها إذا دوره يسمح.
- جهات ومزودون مشتركون يبقون ظاهرين للقراءة، ولا يختارهم المستخدم المقيّد لإنشاء ارتباط متابعة/تنفيذ جديد. يتولى حساب يغطي جميع مناطقهم ذلك.
- المناطق الإدارية للجهة حقل مستقل عن النطاق محلي/عالمي وعن التغطية التجارية. لا يغير شروط مطابقة القطاع والتخصص والبرنامج وشكل الرعاية.
- مناطق المزود تؤخذ من **جميع** روابط التغطية، بما فيها غير النشطة، لمنع تجاوز النطاق بتعطيل رابط.
- البطاقة تضبط نطاق سجلات المتابعة والتنفيذ التابعة لها. تُحجب بيانات الجهات ومرفقاتها إذا كانت خارج نطاق المستخدم أيضًا.
- الإعدادات العامة (القطاعات، التخصصات، البرامج، الكيانات، أشكال الرعاية، المستويات وبنود الصرف) **تبقى حسب الدور الحالي**. لا ندّعي عزلها جغرافيًا لأنها مراجع مشتركة أصلًا.
- صفحة المناطق تعرض المناطق المعيّنة فقط للمقيّد، وإضافة منطقة عامة جديدة متاحة للحساب غير المقيّد بمناطق إذا لديه صلاحية الإضافة.
- مدير النظام الأعلى الحقيقي مستثنى من قيد المناطق. لا يمنح اسم الدور صلاحية المدير الأعلى.

## المحافظة على البيانات

- ترحيلان إضافيان فقط؛ لا حذف أو استبدال أو بذر لبيانات العمل.
- الحسابات الموجودة تبدأ بنطاق «جميع المناطق»؛ لا تتغير أدوارها أو صفحاتها أو منحها.
- الشراكات القديمة لا تُعطى مناطق افتراضية. تبقى متاحة للحسابات غير المقيّدة، ومخفية للمقيّدين حتى تُستكمل المناطق الإدارية.
- يجوز للمسؤول غير المقيّد إبقاء سجل شراكة بلا مناطق أثناء استكمال البيانات؛ إنشاء الجهة للمستخدم المقيّد يحتاج منطقة مسموحة واحدة على الأقل.
- المنطقة غير النشطة المعينة سابقًا تبقى مرئية تاريخيًا ولا يمكن اختيارها لسجل جديد. لا يمكن حذف/إيقاف منطقة مرتبطة بنطاق مستخدم أو شراكة أو مزود أو بطاقة؛ تعرض رسالة الارتباطات المعتادة.
- إجمالي تمويل البطاقة ونسبها يحسبان على كامل البطاقة ولا يُعاد حسابهما على الجهات المرئية فقط. بعض تفاصيل الجهات قد تكون محجوبة، لكن الإجمالي ليس مبلغًا جزئيًا مضللًا.
- سجلات التنفيذ التي تتضمن جهة خارج النطاق تصبح للقراءة فقط؛ لا يحذف الحفظ تلك الجهة خفيةً. الأدلة التاريخية الأصلية تبقى محفوظة، وتُحجب أسماء الجهات غير المتاحة عند العرض.

## التنفيذ

`access_control.regions` هو مصدر القيد: `scoped()` للقراءة، وفحص جميع العلاقات قبل الكتابة. يستخدم EXISTS لتجنب تكرار الصفوف أو تضخيم إجماليات التمويل. القيد يسبق الترقيم والتصدير والعد.

صفحات MVT وطلبات التأكيد الموقعة والروابط المباشرة وخدمات العمل تفحص النطاق على الخادم؛ إخفاء الزر ليس حماية بحد ذاته. خدمات الكتابة تقفل سجل UserAccess داخل transaction قبل إعادة فحص الصلاحيات، ثم تقفل السجل الرئيسي. إدارة المستخدم تكتب سجل الوصول نفسه قبل تعديل المناطق، فتترتب عمليات تغيير النطاق والكتابة المتزامنة.

تعتمد واجهة اختيار المناطق على القوائم القابلة للبحث الموجودة ونافذة تأكيد الحساب الحالية، وتستخدم التصميم العربي RTL وخط Cairo وألوان مكّن. لم تتغير روابط الشريط الجانبي أو ترتيبه.

تعديل `UserAccess` مباشرة عبر ORM/SQL خارج خدمة الإدارة لا يمر بتدقيق الإدارة؛ استخدم صفحة المستخدم أو خدمة الإدارة للعمليات اليومية. أي وحدة جديدة تحتوي بيانات جغرافية تحتاج تسجيل علاقة النطاق وتمرير المستخدم صراحة في قراءاتها وخدماتها.
